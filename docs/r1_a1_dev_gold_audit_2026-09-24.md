The production CTI schema accepts an IPv4 value, including an RFC 1918 address, but accepting an input does not make an external threat-intelligence lookup informative for an internal host. The CTI skill can return `unknown`/`not_found` when no IOC matches. The production network schema accepts domain values, yet the current network skill explicitly reports that **domain lookup is unavailable from flow-only telemetry; DNS/TLS enrichment is deferred**. The matcher requires a tool-name-compatible prediction for each required gold call and only then tests required arguments; a different relevant tool cannot satisfy the gold tool. It correctly reports extra calls and missing calls independently.

**Audit summary:** Seven misses involve a *required CTI lookup of a private source IP* (`001`, `003`, `009`, `010`, `011`, `018`, `019`). Two require network lookup of a domain (`004`, `006`) despite current flow-only limitations; `006` supplies only email-gateway evidence. Three cases have an extra network prediction relative to gold (`001`, `003`, `019`); `003` has a clear unsupported extra call, while the others are confounded by gold ambiguity. The exact matched calls, FP/FN and gold `call_id` in the artifact agree with the matcher; these nine failures do not exhibit a call-assignment defect or argument mismatch.

**Decision before freeze:** Have a reviewer adopt one explicit rule for private-IP CTI (required no-match check versus evidence-relevant only) and one for domain network lookup under available telemetry. Reword requests, gold and categories together in a *new version* if revisions are approved; rerun `dev` under that version and keep the original artifact/15-of-24 result unchanged. Freeze the chosen benchmark and scorer hashes **after** adjudication, before a single frozen evaluation. No frozen case was inspected or run for this audit.
